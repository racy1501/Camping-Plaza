# 客组体验数值流基线

本文件记录 Phase 1 实现时 `camping_plaza/game_engine.py` 的真实生产规则，不改变任何正式参数。正、负只表示数学符号；不表达事件的主观等级。

## 体验账本

每个 `NPCGroup` 保留原有 `total_satisfaction`（最终净值），并新增：

- `positive_experience_total`：实际生效的全部正向 delta 累计；
- `negative_experience_total`：实际生效的全部负向 delta 的绝对值累计。

所有真实体验变化通过 `CampingPlazaEngine.apply_satisfaction_delta` 结算。它继续按 0～100、1 位小数的现有规则截断，因此账本记录的是实际生效值：满分客组再获得正向效果时不虚记未生效的分数。初始化、预约构造和旧快照加载不记入账本；旧快照缺字段时两个累计值均从 `0` 开始。

## 当前满意度来源

| 来源 | 当前 delta / 计算方式 | 正/负 | 当前触发机制 |
|---|---:|---|---|
| 入场绿化 | `+当前 greenery_satisfaction` | 正 | 每组成功首次入场一次 |
| 餐饮套餐 | `+2 / +4 / +6` | 正 | 完成基础 / 中档 / 高档套餐 |
| 免费娱乐 | `+1` | 正 | 完成已计划免费娱乐 |
| 收费娱乐 | `+2 / +4 / +6` | 正 | 完成基础 / 中档 / 高档收费娱乐 |
| 温泉 | `+6` | 正 | 温泉计划成功且容量足够 |
| 帐篷故障 | `-min(10, 当前满意度)` | 负 | 住客入住 broken 帐篷或在住期间发生故障；同次故障只扣一次 |
| 及时维修 | `+本次实际故障扣除值` | 正 | 故障后的第一个可维修窗口内修复成功 |
| 提升服务 | `+5` | 正 | 每个在场客组独立 30% 命中；每天最多两次 |
| 清洁营地 | `+2` | 正 | 每个在场客组独立 70% 命中；每天最多两次 |
| 临时冲突处理失败 | `-2` | 负 | 已排期冲突中，该客组不接受口头调解或小礼物 |

`dining_shortage` 目前只记录未能供餐的经营事件，不直接改变 `total_satisfaction`；温泉容量不足、营位/帐篷不可用也没有直接满意度 delta。它们不是漏记的体验账目。

## 当前评价与需求基线

- 临时冲突基础触发概率为 `0.70`；同气质乘 `0.95`，不同气质乘 `1.05`。客组拒绝处理时才各自扣 `2`。
- 当前星级阈值：`<56` 为 1★，`56–63` 为 2★，`64–71` 为 3★，`72–83` 为 4★，`>=84` 为 5★。
- 离场客组以既有 50% 概率留下评价；次日晨间把待结算评价的整数星级累计为 `total_rating_sum / total_reviews`，即营地整体评价。
- 自然需求使用营地评价比例：无评价时为 `3.0 / 5`，否则为真实平均星级 `/ 5`。经营质量 `S = (评价比例 + (餐饮等级+1)/3 + (娱乐等级+1)/3 + 绿化值/10) / 4`；日间需求为随机取整 `S × 发展度 × 10`，过夜需求为随机取整 `S × 发展度 × 6`，发展度为 `(1 + 已解锁帐篷数/6) / 2`。

## 模拟边界

`tools/simulate_experience_balance.py` 用真实引擎和既有 balanced 开发动作跑离线 SQLite 内存库；不访问或写入生产存档。它只在输出中额外计算 `initial + P - λN` 的候选星级，绝不写入正式评价算法。

## Phase 2A 模拟结果（500 seeds × 20 天）

本节只记录分析结果，不是正式调参决定。模拟使用 seed `20260824..20261323`、既有 balanced 动作和正式引擎，累计 88,774 组离场客人、44,499 条真实评价。

### 负向数值流审计

| 来源 | delta | 数值流分类 | 玩家可经营降低 | 同时已有成本 |
|---|---:|---|---|---|
| 帐篷故障 | `-min(10, 当前满意度)` | A：直接负 delta | 可及时维修恢复净值，但体验账本保留 | 维修 100 金币、决策点、容量损失 |
| 临时冲突不接受处理 | `-2` | A：直接负 delta | 可选择处理方式；当前模拟使用口头调解 | 小礼物时 40 金币 |
| 食材不足 | `0` | B：未恢复时失去餐饮正向收益 | 补货可重试 | 未恢复时失去餐饮收入 |
| 待清洁、营位/帐篷/温泉容量不足、日转夜失败、预约无法接待、收费娱乐/餐饮其他失败 | `0` | B 或 C：视具体原计划是否失去正向或收入 | 容量、清洁、补货、设施建设 | 不收费或失去潜在收入；无直接满意度 delta |

食材不足会设置 `had_food_shortage`，因此是评价负面文案候选；它不改满意度，也不保证该候选一定被选入最终短评。模拟中 0.04% 客组遭遇且未恢复，合计损失 7,105 金币潜在餐饮收入与 132 点潜在正向满意度。

直接负体验中：帐篷故障 3,823 次，影响 4.31% 客组，平均损失 10，贡献 86.32% 负向数值；临时冲突 3,030 次，影响 3.41% 客组，平均损失 2，贡献 13.68%。客组负向事件次数为 0/1/2/3+：93.61% / 6.32% / 0.07% / 0%。

### 评价反馈与需求

真实模拟的全历史评价均值为 3.709；最近 10/20/30/50 条的运行内均值为 3.990 / 3.987 / 3.969 / 3.880。以一段真实 50 条、均值 4.000 的评价序列为基准，只插入确定星级时，5 条 2★使全历史/10/20/30/50 窗口分别变化 -0.020 / -1.000 / -0.500 / -0.333 / -0.180；其后再有 10 条 4★时，对应变化为 -0.019 / 0 / -0.500 / -0.400 / -0.160。

评分每下降 0.5★，`S` 固定下降 0.025；期望日间/过夜需求分别下降 `0.25D` / `0.15D`。本次真实典型状态的 D：早期 0.583、中期 0.796、后期 0.996，对应每 0.5★约少 0.15/0.09、0.20/0.12、0.25/0.15 组日间/过夜需求。

### 候选权重与冲突频率

`N>=10` 客组的 4★比例在 λ=1.00/1.25/1.50/1.75/2.00 时为 48.59% / 31.54% / 22.12% / 10.46% / 5.39%，5★为 2.72% / 0.69% / 0.33% / 0.07% / 0%。`5<=N<10` 在这批样本中为 0 组：当前直接负 delta 只产生 2 或 10/12 的累计值。

冲突候选频率按当前气质分布的期望乘数 1.014 计算；基础概率 15%/20%/25%/30%/35%/40% 时，实际日触发率约为 15.21%/20.28%/25.35%/30.42%/35.49%/40.56%，连续 3 天约为 0.352%/0.834%/1.629%/2.815%/4.470%/6.673%。

## Phase 2B 正式参数

- 临时冲突基础概率正式为 25%；气质乘数与处理、扣分规则不变。
- 客组评价 score 正式为 `total_satisfaction - negative_experience_total`（λ=2）；不改写体验账本或最终满意度。
- 当前营地评分正式从 `review_history` 最近 20 条已结算评价派生；不足 20 条使用全部，历史评价不再因评分窗口被截断。
